背景：
- RemaGraph 是一個輕量記憶工具，用來讓多個 AI agent 在處理任務時自動留下「任務交接、狀態更新、發現限制」。
- 目前 RemaGraph 已提供極簡 CLI：
  - `remagraph init --project <名稱>` （初始化）
  - `remagraph auto --task-id <任務編號> --agent-id <agent名稱> -- <你的實際指令>`
  - 或下載 `remagraph-task.sh` 包裝腳本，一樣兩個環境變數就能用。
- 目標是讓「非技術使用者」也能輕鬆使用，不用自己寫 subprocess 或記複雜指令。
- 指揮塔負責派工給 headless agent（透過 herdr_bridge 的 send_to_agent 或 acp.prompt）。

你的任務：
請在指揮塔的派工流程中，加入自動使用 RemaGraph 記憶的功能。要求如下：

1. 每個派工的任務，自動產生或接收一個 task_id（格式建議：project-日期-描述-短碼，例如 fix-login-20260722-abc123）。
2. 自動決定或接收 agent_id（例如 headless-worker-03 或根據 agent 角色）。
3. 在派工「之前」，自動呼叫 RemaGraph 讀取之前同 task_id 的記憶（現在可用 `remagraph auto --recall-only` 只讀不執行不儲存），並把記憶摘要注入到要送給 agent 的 prompt / text 裡面。
4. 在派工的文字中，明確指示 agent：「請使用以下方式記錄：
   TASK_ID=... AGENT_ID=... remagraph auto --task-id ... --agent-id ... -- <你的工作指令>
   或者直接用 remagraph-task.sh 包裝你的指令。」
5. 盡量讓指揮塔這邊的改動最小、非技術人員也能懂。提供「複製貼上即可用」的程式碼片段。
6. 支援兩種派工方式：
   - 傳統 herdr_bridge send_to_agent
   - acp.prompt / exec_prompt（如果有使用）

最新可用工具（指揮塔強烈建議使用）：
- `remagraph auto --recall-only --task-id XXX --agent-id YYY` （派工前只讀記憶，不跑不存，JSON 輸出）
- `TASK_ID=... AGENT_ID=... remagraph auto --task-id "$TASK_ID" --agent-id "$AGENT_ID" -- <cmd>` （包裝給 agent 執行）
